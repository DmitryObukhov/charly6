Напиши Python-модуль, который реализует физическую модель мира с фиксированным внешним API.

Модуль должен предоставлять публичные функции:

def Init(config_yaml: str) -> None:
    """
    Инициализирует внутреннее состояние физического мира из YAML-конфигурации.
    После вызова Init модуль готов к вызовам Process.
    Повторный вызов Init полностью сбрасывает предыдущее состояние мира.
    """

def GetDefaultConfig() -> str:
    """
    Возвращает строку с YAML-конфигурацией по умолчанию.
    Эта конфигурация должна быть валидной и достаточной для запуска модели без изменений.
    """

def Process(inputs: dict[str, float]) -> dict[str, float]:
    """
    Получает словарь входных управляющих сигналов.
    Все входные значения должны быть числами от 0.0 до 1.0.
    Функция выполняет один шаг симуляции физического мира и возвращает словарь наблюдаемых значений мира.
    Возвращаемые значения — float, не обязательно ограниченные диапазоном 0.0–1.0.
    """

def GetParams() -> dict[str, str]:
    """
    Возвращает словарь внутренних параметров модуля для редактирования.
    """

def SetParam(name: str, value: str) -> None:
    """
    Изменяет значение внутреннего параметра модуля.
    """

def SetParams(params: dict[str, str]) -> None:
    """
    Изменяет значения нескольких внутренних параметров модуля.
    """

def GetVisualization(size: tuple[int, int]) -> Image
    """
    Returns the world Visualization
    """


Внешний интерфейс является стабильным API. Его нельзя менять. Нельзя добавлять обязательные 
аргументы. Внутренняя реализация мира может быть любой, но должна быть изолирована внутри модуля.

Основная идея модуля:

Мир является дискретной физической симуляцией. Каждый вызов Process выполняет один 
шаг времени. Размер шага времени dt задаётся в YAML-конфигурации. Модуль хранит 
внутреннее состояние между вызовами Process: положение объектов, скорости, 
ускорения, энергию, столкновения, температуру, сопротивление среды или любые 
другие параметры, если они предусмотрены конфигурацией.

пример конфигурации YAML:

simulation:
  base: worlds/linear.py
  dt: 0.1
  seed: 42
  input_validation: strict
  max_steps: null

world:
  dimensions: 2
  gravity: [0.0, -9.81]
  bounds:
    x: [-100.0, 100.0]
    y: [0.0, 100.0]
  air_resistance: 0.01

objects:
  - name: agent # agent is a mandatory object
    shape: triangle, 4
    mass: 1.0
    radius: 0.5
    position: [0.0]
    velocity: [0.0, 0.0]
    restitution: 0.8
    friction: 0.2

# fileds in the input dictionary
# Входные значения Process имеют диапазон от 0.0 до 1.0. 
# Они должны преобразовываться в реальные физические значения 
# через min/max из конфигурации. Например, если thrust_x 
# имеет min=-10 и max=10, то вход 0.0 означает -10, 
# вход 0.5 означает 0, вход 1.0 означает 10.
inputs:
  - name:  thrust_x
    min: -10.0
    max: 10.0
  - name:  thrust_y
    min: -10.0
    max: 10.0

# Выходные значения Process имеют диапазон от 0.0 до 1.0. 
# Они должны преобразовываться из реальных физических значений 
# через min/max из конфигурации. 
outputs:
  - name:  hunger
    min: -10.0
    max: 10.0
  - name:  light
    min: -10.0
    max: 10.0


Поведение input_validation:

strict — если вход отсутствует, имеет нечисловое значение или выходит 
за диапазон 0.0–1.0, выбросить ValueError.

clamp — если значение меньше 0.0, заменить на 0.0; если больше 1.0, 
заменить на 1.0.

missing_as_zero — отсутствующие входы считать равными 0.0.

Модуль должен быть детерминированным. При одинаковой конфигурации и одинаковой 
последовательности входов он должен возвращать одинаковую последовательность 
выходов. Если используется случайность, она должна зависеть только от seed 
из конфигурации.

Требования к реализации:

Использовать чистый Python, стандартную библиотеку и PyYAML для разбора YAML.

Сделать код читаемым, с понятными внутренними классами. Например:

WorldState
PhysicalObject
InputMapping
OutputMapping
PhysicsEngine

Но эти классы не должны быть частью публичного API.

Init должен:

разобрать YAML;
проверить корректность конфигурации;
создать внутреннее состояние мира;
сбросить время симуляции в 0.0;
сбросить номер шага в 0.

GetDefaultConfig должен вернуть валидный YAML как строку.

Process должен:

проверить, что Init уже был вызван;
проверить входной словарь;
преобразовать нормализованные входы 0.0–1.0 в физические воздействия;
применить силы к объектам;
выполнить один шаг физической симуляции;
обработать границы мира и простые столкновения с ними;
обновить время и номер шага;
сформировать словарь выходных значений согласно секции outputs;
вернуть dict[str, float].

Физическая модель по умолчанию может быть простой:

двумерный мир;
один объект body;
гравитация;
сила тяги по X и Y;
сопротивление среды;
отражение от границ мира;
трение при контакте с нижней границей.

Численное интегрирование можно сделать методом semi-implicit Euler:

velocity += acceleration * dt
position += velocity * dt

После столкновения с границей скорость по соответствующей оси должна изменяться с учётом restitution.

Ошибки должны быть понятными. Если в конфигурации указан неизвестный объект, неизвестный тип входа или неизвестный output source, нужно выбрасывать ValueError с объяснением.

Добавь в конце файла блок:

if __name__ == "__main__":

В нём покажи минимальный пример использования:

получить дефолтный YAML;
вызвать Init;
несколько раз вызвать Process с thrust_x=0.5, thrust_y=1.0;
напечатать результаты.

Также напиши unit tests для pytest:

тест, что GetDefaultConfig возвращает валидный YAML;
тест, что Init принимает дефолтный конфиг;
тест, что Process возвращает словарь float-значений;
тест, что одинаковые входы дают детерминированный результат после повторной инициализации;
тест, что strict-режим отвергает входы вне диапазона;
тест, что объект под действием gravity меняет координату y.

Не меняй публичный API. Не добавляй внешних зависимостей, кроме PyYAML и pytest для тестов.

Модули с различной имплементацией физики будут сохранены в директории worlds. Используй плагин архитектуру
чтобы можно было поместить мозг в мир. при создании пары мозг-мир проверь совместиомость по параметрам:
- все входы мозга должны быть перечислены в словаре вывода (словарь может содержать больше данных)
В случае несовместиомости выдай подробную диагностику
